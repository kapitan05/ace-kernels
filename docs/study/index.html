Study guide: making the mL1-ACE loss fast on the GPU

This guide teaches the whole project: the loss, why the original implementation is slow, every optimization step (sprints 1-11), how each step is proven correct and measured, and the tooling around it. Every code block on these pages is cut from the repository at build time, and every table is read from a saved benchmark run, so what you read is what the code does.

Result in one line. Our implementation computes the same loss and gradients as the original, 29-75x faster and with 5-14x less peak memory on a Tesla T4 (paper training shapes), and is a drop-in replacement: from ace_kernels.module import HardL1ACELoss, SoftL1ACELoss.

How to use this guide

Read the pages in order; each one follows the same pattern:

  1. Concept: the idea in plain words.
  2. Code: the real implementation, with the lines that matter pointed out.
  3. Worked example: small numbers computed by actually running the code.
  4. Try it: commands for your Mac (tests, CPU runs). Copy button on the right.
  5. Evidence: the plot or table from a GPU run that proves the claim.
  6. Self-check: questions with hidden answers. Answer before you open them.

GPU numbers come from Kaggle Tesla T4 runs stored in results/kaggle/<commit>-<job>/; you do not need a GPU to study them. Rebuild this guide any time:

$ uv run python -m ace_bench.figures && uv run python -m ace_bench.study

writes docs/study/*.html; then open docs/study/index.html

Self-check: Why is each optimization a separate registry entry instead of one improved implementation?
So every speedup (or slowdown) is attributable to exactly one change: the ablation table compares neighbours that differ in one idea. It also keeps the earlier versions runnable as baselines and as test oracles for the later ones.
