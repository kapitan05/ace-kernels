4. Triton kernels: privatized histograms, fused backward, fused softmax

Sprints 5-8 replace the PyTorch internals with GPU kernels written in Triton: Python-syntax kernels compiled to GPU code, where you program a block of data at a time instead of single threads.

Concept: the Triton programming model in 6 lines

  • A kernel runs as many independent programs (a grid). tl.program_id(axis) tells a program which piece of the data it owns.
  • Each program works on whole blocks: offs = pid * BLOCK + tl.arange(0, BLOCK) is a vector of BLOCK indices, and tl.load(ptr + offs, mask=offs < N) loads them.
  • Values live in registers; tl.sum(x, axis=0) reduces a block inside the program.
  • tl.constexpr arguments are compile-time constants: if ACT == 1: is resolved when compiling, so one source gives specialized kernels without runtime branches.
  • @triton.autotune tries several BLOCK sizes / warp counts on first call and keeps the fastest per input-size key.
  • tl.atomic_add is the only way programs combine results in global memory.

Our grid: axis 0 = blocks of voxels, axis 1 = batch element. (It was the other way round first; CUDA limits grid axis 1 to 65535 programs, which a 256^3 volume exceeds. The fix and a regression test are in Sprint 6.)

The forward kernel: a private histogram per program

Each program loads BLOCK voxels, computes their bin, builds the one-hot matrix [BLOCK, K] in registers, sums it over voxels (tl.sum) into a private K-bin histogram, and publishes it with one atomic add per bin and statistic. Collisions drop from millions to a few thousand:

Exactness. The bin of a probability must match the reference bit-for-bit, or the loss would differ for voxels on edges. The kernel compares against the reference's own float32 edge tensor (torch.linspace(0, 1 + eps32, K + 1)) with the same comparison as torch.bucketize (right=False: count of edges < p). Edge-exact inputs are golden cases (bin-edges-left/right), and test_hard_stats_match_torch requires exactly equal bin counts.

Self-check: Why are atomics per slice reduced from N to 3 K N / BLOCK?
Each program handles BLOCK voxels and issues one atomic per bin (K) for each of the 3 statistics: N / BLOCK programs x 3 K atomics.
Self-check: Why must forward and backward use the same exp/softmax function?
The bin of a voxel is decided by its probability. If the backward recomputed a probability that differs by 1 ulp and crosses a bin edge, the voxel would use another bin's coef: a wrong gradient for that voxel.
Self-check: Why does the backward kernel tile all channels of a voxel together?
The softmax backward needs sum over channels of p_c g_c for each voxel; having all channels in one program keeps that sum in registers instead of another pass.
